# Control Checklist

> Detection questions, not exploit instructions. Each row asks "is this control present, and can it be
> bypassed?" Mark `present`, `absent`, `N/A`, or `cannot determine`.

## Authentication

- Are credentials verified server-side on every request, or only at login?
- Is the token signature verified, with the algorithm pinned (no `none`, no key confusion)?
- Are password hashes slow and salted (Argon2id, scrypt, bcrypt) with sane parameters?
- Is MFA enforced for privileged operations, or only offered?
- Are reset tokens single-use, short-lived, and bound to the account?
- Is session fixation prevented (new session on privilege change)?
- Are timing differences in comparison avoided for secrets?

## Authorization

- Is every object access checked against the *caller's* ownership, not a client-supplied id?
- Is the tenant/org predicate present in every query, including aggregates and exports?
- Are role checks enforced server-side, at the handler, not only in the UI or router?
- Can a user escalate by editing a request body field (`role`, `tenant_id`, `is_admin`)?
- Are admin endpoints on a separate authorization path, or do they rely on URL obscurity?
- Is authorization checked *before* the side effect, including in batch and async paths?
- Do background jobs run with the originating user's authority or a broader service identity?

## Input handling

- Is input validated by an allowlist with a defined grammar, or by denylist?
- Are lengths, counts, and nesting depth bounded before parsing?
- Is there a canonicalization step before validation (Unicode normalization, path resolution)?
- Are unsafe sinks reached with unvalidated input: shell, `eval`, template, SQL, LDAP, XPath, regex?
- Are file paths resolved and confined to an allowed root, with symlinks considered?
- Are archive extractions bounded (zip bombs, path traversal, symlink escape)?
- Are redirects restricted to allowed hosts?

## Output and encoding

- Is output encoded for its context (HTML body, attribute, JS, URL, CSS, SQL, shell)?
- Is auto-escaping disabled anywhere, and is that justified per case?
- Are error messages free of stack traces, SQL, internal paths, and secrets?
- Are CSV/spreadsheet exports protected against formula injection where relevant?
- Are headers that affect security (CSP, HSTS, content-type, cache) set deliberately?

## Cryptography

- Is the primitive appropriate for the purpose (AEAD for encryption, HMAC for integrity)?
- Are nonces/IVs unique per key, and generated by a CSPRNG?
- Is key material stored outside source, rotated, and scoped per environment?
- Are comparisons of secrets constant-time?
- Is home-grown crypto present? (Almost always a finding.)
- Is randomness from a cryptographic source where unpredictability matters?

## Secrets and configuration

- Are secrets in env, vault, or KMS — not in the image, repo, or client bundle?
- Are secrets excluded from logs, traces, error reports, and crash dumps?
- Are debug endpoints, admin panels, and sample credentials disabled in production config?
- Are defaults fail-closed (deny by default, TLS required, CORS restricted)?
- Is configuration validated at startup rather than silently defaulting?

## Sessions and state

- Are cookies `HttpOnly`, `Secure`, `SameSite` as appropriate?
- Is CSRF protected for state-changing requests, including form and JSON variants?
- Is logout server-side invalidating the session, not just clearing the cookie?
- Are concurrent sessions and token lifetimes bounded?
- Is state stored client-side signed and integrity-protected?

## Deserialization and parsing

- Are untrusted inputs deserialized with a safe format and a strict schema?
- Is polymorphic type resolution restricted to an allowlist?
- Are parser versions current for known CVEs in the parsing library?
- Are XML parsers configured to disable external entities?

## Dependencies and supply chain

- Are lockfiles committed and integrity-checked?
- Are install scripts disabled or reviewed where the ecosystem allows it?
- Are dependencies pinned and updated through a reviewed process?
- Is the dependency's license and maintenance status acceptable?
- Are build and release artifacts produced from a reproducible, access-controlled pipeline?

## Logging, monitoring, and privacy

- Are security-relevant events logged (auth failures, authorization denials, privilege changes)?
- Do logs avoid credentials, tokens, full PII, and request bodies with secrets?
- Is there an audit trail for admin actions, tamper-evident where required?
- Are alerts defined for anomalous rates, not just for errors?

## Race conditions and resource limits

- Is check-then-act atomic (DB constraint, conditional update, lock)?
- Are per-user and global rate limits enforced where abuse is possible?
- Are expensive operations bounded (pagination cap, query timeout, upload size)?
- Can a request cause unbounded memory growth through a single payload?

## Using the register

Copy the headings that apply to the reviewed surface into the report, one row per control, with the
evidence pointer. A register with thirty rows of `N/A` is worse than five rows of substance.
